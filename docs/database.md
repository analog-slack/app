# База данных и миграции

В API используется PostgreSQL, а описание структуры базы и история изменений хранятся в `apps/api/prisma/`:

- `schema.prisma` — текущая схема, источник истины для моделей Prisma.
- `migrations/` — последовательность версионируемых SQL-миграций. Эти файлы нужно добавлять в Git.

## Таблицы

| Таблица                 | Назначение                                                                                                         |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `users`                 | Учётные записи: email, имя пользователя, хеш пароля, аватар и состояние аккаунта.                                  |
| `workspaces`            | Рабочие пространства; у каждого есть владелец.                                                                     |
| `workspace_members`     | Участники рабочих пространств и их роли; один пользователь может состоять в пространстве только один раз.          |
| `workspace_invitations` | Приглашения в рабочие пространства: email, хеш токена, статус и срок действия.                                     |
| `teams`                 | Команды внутри рабочего пространства; название уникально в пределах пространства.                                  |
| `team_members`          | Участники команд и их роли.                                                                                        |
| `projects`              | Проекты рабочего пространства; проект может быть связан с командой.                                                |
| `project_members`       | Участники проектов и их роли.                                                                                      |
| `channels`              | Каналы проекта, включая описание, видимость и признак архивации.                                                   |
| `channel_members`       | Участники каналов.                                                                                                 |
| `conversations`         | Личные или групповые беседы рабочего пространства.                                                                 |
| `conversation_members`  | Участники бесед.                                                                                                   |
| `messages`              | Сообщения в каналах или беседах; поддерживают ответы на сообщения и редактирование/удаление.                       |
| `message_reactions`     | Реакции пользователей на сообщения; комбинация сообщения, пользователя и эмодзи уникальна.                         |
| `task_statuses`         | Статусы задач проекта и их порядок; имя и позиция уникальны в проекте.                                             |
| `tasks`                 | Задачи проекта: статус, автор, исполнитель, приоритет, срок и позиция. Задачу можно связать с исходным сообщением. |
| `task_history`          | История изменений задач: кто изменил поле и его старое/новое значение.                                             |

Связи между таблицами заданы внешними ключами. Поля в `schema.prisma` используют `camelCase`, а `@map` / `@@map` связывают их с названиями колонок и таблиц в `snake_case` в PostgreSQL.

## Локальная разработка

### Первый запуск или новая локальная база

Скопируйте `apps/api/.env.example` в `apps/api/.env`, убедитесь, что `DATABASE_URL` указывает на нужную базу, и запустите PostgreSQL вместе с остальной локальной инфраструктурой:

```bash
docker compose up -d
pnpm --filter api db:migrate
```

`db:migrate` применит уже сохранённые миграции и сгенерирует Prisma Client. Не добавляйте `--name init`: начальная миграция уже хранится в репозитории.

### Просмотр данных

Чтобы просматривать таблицы и записи локальной базы через браузер, запустите Prisma Studio из корня репозитория:

```bash
pnpm --filter api exec prisma studio
```

Откройте http://localhost:5555. Studio подключается к базе, указанной в `DATABASE_URL` файла `apps/api/.env`; перед запуском убедитесь, что PostgreSQL запущен и URL указывает на нужную базу. Чтобы завершить работу Studio, остановите команду сочетанием `Ctrl+C`.

### Изменение схемы

1. Внесите изменение в `apps/api/prisma/schema.prisma` — не меняйте схему базы вручную.
2. Создайте и примените миграцию в локальной среде, задав короткое имя по смыслу изменения:

   ```bash
   pnpm --filter api db:migrate --name add_channel_settings
   ```

3. Просмотрите новый каталог в `apps/api/prisma/migrations/`, проверьте SQL и добавьте миграцию вместе с изменённым `schema.prisma` в Git.
4. Проверьте итоговое состояние командой:

   ```bash
   pnpm --filter api exec prisma migrate status
   ```

`db:migrate` вызывает `prisma migrate dev`: команда предназначена для разработки, создаёт миграцию при изменениях схемы, применяет ожидающие миграции и обновляет Prisma Client. Не редактируйте миграции, которые уже применялись или попали в общую ветку; для следующих изменений создавайте новую миграцию.

## Применение в production

Для production используйте только уже созданные и проверенные миграции:

```bash
pnpm --filter api db:deploy
```

Команда вызывает `prisma migrate deploy`: применяет ожидающие миграции и не создаёт новую. В production Docker API-контейнер выполняет `db:deploy` при старте. Перед выкладкой проверьте `DATABASE_URL`, сделайте резервную копию базы и проверьте SQL миграции. Не запускайте `migrate dev` против production-базы.

## Важно

- `schema.prisma` и миграции должны изменяться и попадать в Git вместе.
- Не используйте `prisma db push` для обычной разработки проекта: он меняет базу без создания миграции в истории.
- `prisma migrate reset` удаляет данные и пересоздаёт локальную базу; используйте только если действительно готовы потерять её содержимое. Никогда не запускайте reset на общей или production-базе.
- Идентификаторы таблиц — UUID. В текущей схеме для них не задано автоматическое значение по умолчанию, поэтому приложение должно передавать UUID при создании записи.
